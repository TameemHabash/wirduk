Wirdak — design direction

A proposal for review before the screens are built. Colors, fonts, spacing and the main screens. The phone screens below are mockups in HTML; the dhikr texts in them are real texts from the app's database.

1. Direction “Paper and ink”

The app should feel like a calm, well-printed book: warm paper, deep teal ink, and a little gold from the logo. Reading comes first. Everything else stays quiet.

One job per screen

Home finds a category. The reader shows one dhikr and counts. Nothing competes with the text.

Big, easy targets

Tap anywhere to count. Swipe to move. Large text, generous line height for full tashkeel.

Quiet details

Fadl and source are small and faded. Gold is only for progress and highlights, never for long text.

What I looked at

  • Pillars — praised for a clean, minimal design, a gentle palette, no ads and no tracking.
  • Current adhkar / tasbih apps (Dhikrly, Tawakkul, Sabha, Tasbih Counter): common good patterns are a whole-screen tap zone, a circular progress ring, large Arabic text, light and dark modes, and grouping by time of day.
  • A Rest of World piece notes most dhikr apps keep a functional, minimal look, close to the physical tasbih.

What Wirdak adds: a real book-like reading surface, a time-aware home (morning or evening first), and source details that are there for those who want them without getting in the way.

2. Colors from the logo: teal, gold, cream

Contrast is measured (WCAG). Body text is far above 7:1. The faint color for fadl and source is at least 4.5:1 on the reading card, so it stays readable. Gold is under 4.5:1 in light mode, so it is used for rings, icons and badges only.

3. Typography

Two families: one for the interface, one for the dhikr text. Dhikr text uses a generous line height (set per font) so tashkeel above and below never touches the next line. Numbers use Western digits (23), inside right-to-left Arabic text.

License problem with KFGQPC Uthmanic Hafs (the default you asked for). Its license says: “This Font is the property of King Fahd Glorious Quran Printing Complex, and may not be reproduced, modified without the express written approval of King Fahd Glorious Quran Printing Complex.” Shipping it inside the app is reproducing it, so it needs written approval from the Complex. Decided: the default is Amiri Quran (open license, OFL-1.1). If written approval for KFGQPC comes later, adding it is a small change.

5b. Long adhkar true size — try it

These phones are drawn at real size (a Pixel 7 is 412 dp wide), so the text size is what you will see on a phone. The dhikr area scrolls on its own; the header, progress and counter stay fixed. Try it: scroll the text with the mouse wheel or trackpad — it does not count. Click anywhere on the phone — it counts. On the phone the same rule applies: a scroll or drag never counts, only a short tap.

Length in numbers: the median dhikr is 140 characters and 90% are under 395. Only a few are long like these.

Open question: how a report reaches GitHub

GitHub only lets you attach images by hand on its web page, or through its API with a secret token. A token must never be inside the app (anyone could extract it). Also, the wirdak repo is private, so people outside cannot open issues there. The three workable options:

OptionFor the person reportingFor you
A. The app sends it
(through a tiny free relay)		No GitHub account needed. Screenshots are attached automatically. One tap: “إرسال”.Issues (with screenshots) appear in your private repo, so reports stay private. Needs a small free Cloudflare Worker that holds the GitHub token, with limits against spam. You create a free Cloudflare account once.
B. Open GitHub’s pageNeeds a GitHub account and must sign in. Title and app details are filled in, but screenshots must be added by hand on the page.No server. Issues must go to a public repo, so reports are public.
C. EmailNo account. The email app opens with the report and screenshots attached.No server, private. You get emails and create GitHub issues yourself.
